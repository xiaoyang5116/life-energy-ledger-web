# FIRE Tracker PRD v1.2 整理稿

## 1. 产品定位

FIRE Tracker 是一款移动端优先的极简记账 Web App / PWA。它不是传统账本，而是把每一笔现金流记录翻译成“生命能量”的复盘工具。

一句话定位：

> 用最低摩擦记录现金流，再通过生命流向理解钱背后消耗、补充或买回了多少生命能量。

产品的核心问题不是“我花了多少钱”，而是：

- 这笔钱对应多少生命能量？
- 这段生命能量流向了哪里？
- 它带来了足够满足感吗？
- 它是否符合长期价值观？
- 如果我不必为了钱工作，我还会这样花吗？
- 我是否正在把生命能量投向更自由的未来？

## 2. 核心用户

MVP 首发用户是产品作者本人。

这意味着早期目标不是覆盖所有记账场景，而是验证一个强个人需求：

> 能否用极低成本持续记录现金流，并通过周末复盘看清生命能量的流向。

## 3. 核心哲学

### 金钱是生命能量

产品的第一表达单位是小时，而不是元。金额是事实，生命能量才是用户真正能感知的成本。

```text
生命能量小时数 = 金额 / 真实时薪
```

真实时薪按工作收入扣除通勤成本后计算：

```text
真实时薪 = (税后月工资 - 月通勤成本) / (月工作时间 + 月通勤时间)
```

### 录入只记录事实

快速录入阶段只问三件事：

- 什么时候？
- 多少钱？
- 叫什么？

录入阶段不要求选择支出、收入、储蓄、退款或转账。除非系统已经命中历史规则，否则录入成功后的反馈也不默认称为“消耗”。

### 复盘才做判断

复盘现金流记录时，用户判断的不是传统分类，而是生命流向：

- 这类生命能量流向哪里？
- 是否带来满足感？
- 是否符合长期价值观？
- 如果不用为了钱工作，还会不会这样花？

### 系统记住重复判断

第一次认真复盘，之后自动复用。相同描述再次出现时，系统自动带出生命流向、现金流方向、统计影响和复盘判断。

## 4. 产品差异化

| 传统记账产品               | FIRE Tracker                     |
| -------------------------- | -------------------------------- |
| 以金额为核心               | 以生命能量为核心                 |
| 录入时区分收入、支出、分类 | 录入只记录事实，复盘再判断       |
| 关注分类、预算、报表       | 关注生命流向、满足感、自由感     |
| 依赖普通账目类别           | 分类围绕生活价值与生命能量       |
| 每笔手动分类               | 系统复用判断，自动复盘重复现金流 |
| 工具属性强                 | 自我觉察和个人自由仪表盘属性强   |

## 5. 核心使用场景

### 发生现金流后极速记录

用户消费、收到工资、退款或投资赎回后打开应用，输入金额、描述、日期，系统立即换算生命能量。

示例：

```text
金额：35
描述：麦当劳
反馈：这笔金额约等于 0.35 小时生命能量
```

### 重复现金流自动复盘

用户第一次把“麦当劳”复盘为“生存维持”后，下次再次记录“麦当劳”，系统自动复用同一生命流向和复盘判断。

### 周末复盘

待复盘页按描述分组展示尚未理解的现金流，用户对一组相同描述的记录统一判断。

### 查看自由进度

首页展示本月生命消耗、自由积累、收入补充、待复盘数量等核心指标。

### 记录收入、退款和储能解冻

v1.2 不只处理消费，也处理工资、副业、退款、投资赎回等现金流。用户仍然只输入正数金额，系统通过生命流向判断现金流方向和统计影响。

## 6. v1.2 的关键产品决策

1. `amount` 统一按正数存储。
2. 录入阶段不选择支出或收入。
3. 生命流向内置 `direction`，用于判断现金流方向。
4. 生命流向内置 `statEffect`，用于决定统计方式。
5. 用户只看生命流向，不感知 `statEffect`。
6. 统计基于 `statEffect`，不依赖金额正负号或分类名称。
7. 待复盘页按 `descriptionKey` 分组，而不是逐笔处理。
8. 相同描述通过自动复盘规则复用用户判断。

## 7. 产品判断标准

MVP 成功不看功能复杂度，而看是否形成持续使用闭环：

- 记录是否足够快。
- 周末复盘是否真的带来觉察。
- 自动复盘是否明显降低长期负担。
- 用户是否更理解自己的消费、收入和自由进度。

核心口号：

> 别只记录你花了多少钱。看见你的生命能量流向了哪里。
