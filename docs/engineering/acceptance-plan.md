# 验收与开发计划

## 1. 验收标准

### 初始化配置

- 用户能填写税后月工资、月通勤成本、每日工作小时、每月工作天数、每日通勤小时。
- 系统能正确计算真实时薪。
- 设置页能展示当前真实时薪。
- 修改任一参数后，真实时薪自动更新。

### 极速录入

- 用户输入金额、描述和日期后，点击确认能创建现金流记录。
- 用户不需要选择支出 / 收入。
- 金额按正数存储。
- 系统能计算 `energyHours`。
- 系统能生成 `descriptionKey`。
- 命中历史规则时，记录自动进入 `auto_reviewed`。
- 未命中历史规则时，记录进入 `unreviewed`。

### 第一次复盘

- 待复盘页能展示未复盘分组。
- 每组展示笔数、总金额、总生命能量。
- 用户能选择生命流向分类。
- 系统能根据生命流向自动带出 `direction` 和 `statEffect`。
- 当 `statEffect = consume` 时，用户能完成三项判断。
- 当 `statEffect` 为收入、退款、解冻等非消费类时，可以跳过三项判断。
- 确认后，分组内记录变为 `reviewed`。
- 系统创建或更新 `AutoReviewRule`。

### 自动复盘

- 再次录入相同 `description` 时，系统命中历史规则。
- 系统自动填充 `categoryId`、`direction`、`statEffect` 和三项判断。
- 记录状态变为 `auto_reviewed`。
- 待复盘页默认不展示该记录。

### 金额异常

- 当相同 `description` 的金额明显高于历史平均时，系统不直接自动复盘。
- 记录状态变为 `suggested`。
- 待复盘页展示该分组。
- 用户可以确认或重新判断。

### 统计

- 首页或统计页能展示本月生命消耗。
- 能按生命流向分类展示小时数。
- 能展示值得 / 中性 / 后悔的生命消耗。
- 能展示符合 / 中性 / 违背价值观的生命消耗。
- 能展示可能因打工生活产生的工作依赖成本。
- 能展示自由积累小时数。
- 能展示收入补充。
- 能展示退款抵消小时数。
- 能展示储能解冻小时数。
- 统计必须基于 `statEffect`，不能依赖金额正负号。

## 2. 推荐首版开发拆分

### Day 1：项目基础

- 路由结构
- 基础布局
- 本地数据模型
- 本地持久化方案

### Day 2：初始化设置

- 设置页
- 真实时薪表单
- 参数校验
- 真实时薪计算
- 本地存储

### Day 3：极速录入

- 金额输入
- 描述输入
- 日期默认今天
- 生命能量计算
- `descriptionKey` 生成
- 成功反馈
- 未命中规则进入 `unreviewed`

### Day 4：默认生命流向与记录列表

- 默认生命流向分类
- 生命流向内置 `direction` 和 `statEffect`
- 现金流记录列表
- `reviewStatus` 状态展示
- 本地持久化

### Day 5：待复盘页

- 按 `descriptionKey` 分组
- 分组展示总金额和总生命能量
- 复盘底部面板
- 生命流向选择
- 根据 `statEffect` 决定是否展示三项判断

### Day 6：自动复盘规则

- 创建 `AutoReviewRule`
- 相同描述自动复盘
- 自动带出生命流向、`direction`、`statEffect`
- 金额异常进入 `suggested`
- 规则使用次数与平均金额更新

### Day 7：首页统计与打磨

- 基于 `statEffect` 计算统计
- 本月生命消耗统计
- 自由积累统计
- 满足感统计
- 待复盘数量
- 移动端适配
- 空状态与反馈文案

## 3. 开发时的防偏提醒

每个新功能进入 MVP 前，先问：

> 它是否增强生命能量感知、价值判断或自由进度？

如果不能，就不进入 MVP。

## 4. 高风险点

### 复盘负担过重

应优先保证：

- 录入阶段不思考。
- 待复盘页按描述分组。
- 重复描述自动复盘。
- 收入、退款、解冻类减少复盘问题。

### 统计语义混乱

必须坚持：

- `amount` 不表达方向。
- `direction` 表达方向。
- `statEffect` 表达统计归属。
- UI 不暴露 `statEffect` 给普通用户。

### 产品滑向普通记账

避免优先做复杂预算、账户、报表和资产管理。首页应像自由仪表盘，而不是财务后台。
